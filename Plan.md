# Plan.md — Android APK

**Branch:** `feature/android-apk` (create from `main` if it does not exist). Follow `CLAUDE.md` for process. Work top to bottom, tick boxes, commit per task. The owner merges.

Legend: `[ ]` todo, `[x]` done, `BLOCKED` = failed after three attempts and a fallback.

## Summary

Ship Hundred Block as an installable **Android APK** for phones and tablets made in 2020 or later, built from the same Flutter codebase as the website. Gameplay, scoring, data pack, stats shape and the web build do not change. A future feature commit must reach both targets with no per-target work beyond `lib/platform/`.

## Scope

**In:**
- `android/` project generated by Flutter, committed.
- A native `lib/platform/` implementation (storage, visibility, export, Ko-fi link) selected without disturbing web or `flutter test`.
- Native-map fixes so the existing `maplibre_gl` code works on Android (no JS library setup, correct label pixel scaling).
- Phone-sized layout checks (360x640 dp and up) and Android back-button behavior.
- A Docker-only build: an `android` compose service on the **existing** Flutter image, `scripts/build_android.sh`, a Gradle cache volume.
- A CI job that builds the APK and uploads it as an artifact.
- A static check that the release APK has no `INTERNET` permission.
- Docs: README, PRD, HANDOFF (device test plan, signing steps), DECISIONS.

**Out (do not build):** Play Store listing or AAB publishing, iOS, a native Windows app, in-app updates, importing web stats into the app (export JSON stays the only transfer path), push notifications, any gameplay, scoring, data or export-shape change, any new city.

## Behavior

- **Devices:** Android 10 (API 29) or newer, phones and tablets, 2020 and later. Set `minSdk 29` (log in `DECISIONS.md`). Portrait and landscape both work; no orientation lock.
- **Offline and no outbound requests:** the release manifest has no `INTERNET` permission. The map uses the inline blank style and bundled GeoJSON, so nothing is fetched. Ko-fi opens in the system browser on tap only.
- **Storage:** same keys and same JSON as web (`hb.games.v1`, `hb.kofi.v1`), kept in `shared_preferences`. Bad or missing storage never crashes the app. Read stays non-throwing; write may throw when storage fails, as in the interface contract.
- **Timer:** the round timer pauses when the app goes to the background (lifecycle `paused`/`hidden`/`inactive`) and resumes on return, matching the web visibility behavior.
- **Export:** the Stats export opens the Android share sheet with the version 1 JSON as a `.json` file (the shape is unchanged). The tap-to-export flow is the only thing that triggers it.
- **Back button / gesture:** on the game screens it asks the same quit confirmation as the in-app quit control; on Home it exits the app. It never silently abandons a game.
- **Layout:** no clipped or overflowing UI at 360x640, 412x915 and 800x1280 dp, portrait and landscape, with large text scale. Tap targets stay at least 48 dp. System bars and display cutouts do not cover controls (edge-to-edge safe).
- **Map:** pan, pinch zoom and tap-to-guess work by touch. Landmark labels sit on their dots at every zoom and device pixel density.
- **Version:** `pubspec.yaml` `version: 1.0.0+1` supplies `versionName` and `versionCode`. Bump the build number for every APK handed out.

## Tasks

- [x] 1. **Branch and project.** Create the branch. Run `flutter create --platforms=android --org <id> .` inside the container (it must not overwrite `lib/`, `pubspec.yaml` changes or `web/`; review the diff). Set app name `Hundred Block`, `minSdk 29`, keep `targetSdk` at Flutter's default. Confirm `.gitignore` covers `android/local.properties`, `android/key.properties`, `*.jks`, `*.keystore`, `android/.gradle/`, `android/app/build/`. Log in `DECISIONS.md`.
- [x] 2. **Docker build.** Add an `android` service to `docker-compose.yml` using the same `hundredblock-flutter` image (same pinned Flutter; do not add a second Flutter image) with a named `gradle-cache` volume at `/root/.gradle` and the existing `pub-cache`. Add `scripts/build_android.sh` (`flutter pub get`, then `flutter build apk --release`, print the APK path and size). First check what the pinned image already contains (`flutter doctor -v`, `sdkmanager --list_installed`, `java -version`). Only if something is missing, add it in a thin Dockerfile layer `FROM hundredblock-flutter` in `docker/` with pinned versions, and note the pin and reason in `DECISIONS.md`. Do not use `docker compose down -v` or any volume prune.
- [x] 3. **Platform split.** Make `lib/platform/platform.dart` pick web, native or stub without breaking the VM tests. Note that `dart.library.io` is true on the VM, so a plain `dart.library.io` branch would pull plugins into `flutter test`. Preferred: web (`dart.library.js_interop`) and native (`dart.library.io`) conditional exports, with `flutter test` using the existing fakes through injection into `loadDefaultServices` (check how tests construct services today and keep them passing unchanged). Fallback: a build-time `--dart-define=HB_PLATFORM`. Log the choice. Game code must not import a platform file directly.
- [x] 4. **Native platform services** in `lib/platform/platform_native.dart` (each behind the existing interface):
  - Storage: `shared_preferences`. It loads asynchronously, so preload it before `runApp` and hand `KeyValueStorage` a synchronous view over the cached instance. Writes persist in the background; a failed write surfaces as a thrown error where the interface allows, as on web.
  - Visibility: `WidgetsBindingObserver` lifecycle to `VisibilitySource`.
  - Export: `FileDownloader` writes the JSON to a temp file and calls `share_plus`. Keep the filename and content identical to web.
  - Ko-fi: `LinkOpener` via `url_launcher` in external-browser mode. Add the `https` VIEW intent to the manifest `<queries>`.
  - Each new package gets a pinned version and a `DECISIONS.md` line.
- [x] 5. **Native map fixes** (`lib/main.dart`, `lib/map/maplibre_street_map.dart`). Skip the `MapLibreMap.webLibrarySource` / `Uri.base` setup unless on web (`kIsWeb`). Make landmark label placement correct on Android: native `toScreenLocation` is expected to return physical pixels, so divide by `devicePixelRatio` there (verify the plugin's behavior from its source first; do not assume). Put the conversion in a small pure function with unit tests. Confirm the plugin makes no network request with `kBlankMapStyle` (it has no sources, glyphs or sprites). No Burbank strings in `lib/` (the guard test must pass).
- [ ] 6. **Back button, lifecycle, system UI.** Wrap game screens in `PopScope` so the Android back action shows the existing quit confirmation; Home exits. Use `SafeArea` or equivalent so controls clear system bars and cutouts. Widget tests for the back-confirm path using the test back-button hook.
- [ ] 7. **Phone layout.** Add widget tests rendering Home, Length, Round, Summary and Stats at 360x640, 412x915 and 800x1280, portrait and landscape, and with large text scale, asserting no overflow and tap targets of at least 48 dp (extend the existing large-text and layout tests rather than starting new ones). Fix whatever fails, changing layout only, not behavior. Also add a 360x640 case to `e2e/tests/viewport.spec.ts` (Chromium) if it is cheap, since the UI code is shared.
- [ ] 8. **Icon and name.** Add launcher icons from the existing app icon. Use the `flutter_launcher_icons` dev dependency (log it) or the generated mipmaps, whichever runs in the container without host tools. App label `Hundred Block`.
- [ ] 9. **Signing.** Default build is debug-signed so any dev can produce an installable APK with no secrets. Add optional release signing that reads `android/key.properties` and a keystore from an ignored path; if the file is absent, fall back to debug signing and print a clear warning. Add a documented one-time command to generate the keystore with `keytool` inside the container, and a warning in `HANDOFF.md` that losing the keystore means no updates over the installed app. Never commit keystores, passwords or `key.properties`.
- [ ] 10. **APK checks.** Add `scripts/check_apk.sh` (runs in the container with the SDK build-tools): fail if the release manifest requests `INTERNET` or any other dangerous permission; print the declared permissions, `minSdk`, `versionName`, `versionCode` and size; confirm the city pack assets are inside the APK. - [ ] 12. **Docs.** `README.md` (how to build the APK, how to install it), `PRD.md` (Android target, devices 2020+, behaviors above; do not edit archived plans), `HANDOFF.md` (device test plan, signing steps, install via `adb` or file copy, that the app and website update separately, how to bump the version), `DECISIONS.md` entries for `minSdk`, application id, packages, platform-split choice, signing default. ## Exit criteria (run and record)

- [ ] `dart format --set-exit-if-changed .`, `flutter analyze` and `flutter test` pass, including the no-hardcoding guard.
- [ ] `docker compose run --rm android sh scripts/build_android.sh` produces `build/app/outputs/flutter-apk/app-release.apk` from a clean checkout using Docker only.
- [ ] `check_apk.sh` passes: no `INTERNET` permission, `minSdk` 29, city pack inside the APK.
- [ ] Web release build and the full `e2e` suite still pass; `git diff main --stat` shows no changes to scoring, data packs, pipeline, storage keys or export shape.
- [ ] Layout widget tests pass at 360x640, 412x915 and 800x1280, portrait and landscape.
- [ ] Docs updated; `PROGRESS.md` updated.
- [ ] **Owner device test (human, not blocking the archive):** install on at least one phone and one tablet from 2020 or later; play a 10-round game; check the map, timer pause on app switch, back button, export share sheet, Ko-fi link, airplane-mode play, and that stats survive a force-close. Record results in `HANDOFF.md`. Docker on Windows cannot run an emulator, so this step cannot be automated.
